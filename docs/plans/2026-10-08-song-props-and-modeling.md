# 曲库道具与装饰制作方案

2026-10-08。策划提案，未修改运行时功能或卡片归属。歌曲画面已核对，物件名称、数值和搭建方式是设计转译，不是作者的官方解释。

## 当前问题

- 本地卡库当前有 102 首。已有九种道具技能、六类装饰模型，但大量歌曲回退为同一“回声唱片亭”。
- 专属名称不等于专属模型：晴天与樱花草共用花园，我记得只是亭子加唱片。需要从歌曲的具体画面重新设计轮廓与细节。
- 卡片归属仍有按榜单排名分配地图、载具的规则。未来应逐首登记稳定归属；不要未经审阅转换玩家已有的载具、地图、装扮和道具卡。
- 世界编辑器统一以中心距离 4 判断装饰冲突；骑行按列表每隔 9 米摆放，忽略物件尺寸。较大的秋千、山坡、观景台接入前，需要补占地与道路净空判断。

## 不变的规则

- 一首歌只有一种功能。用户认可的八种道具继续作为道具，不再设计对应装饰：《心墙》《你要的全拿走》《至少还有你》《勇气》《茶汤》《冻结》《倒数》《反方向的钟》；《朋友》也保留现有道具归属。
- 暂不增加更多道具机制。现有防御、吸币、复活、冲刺、回复、冻结、双倍、回溯已经覆盖主要玩法。
- 每张装饰卡提供一件完整可放置物件；一件物件内的花、树、座椅都是模型部件，不分别扣卡或重复加装饰值。
- 继续使用库存守恒和现有世界倍率公式。首批换造型时保持已配置歌曲的数值，避免同时改变视觉与经济。
- 文案独立采集真实评论；不把本文件的设计描述当成金卡文案，也不生成新的煽情文案。

## 搭建路线

1. 建模前为每首写四项：歌词/MV依据、核心轮廓、占地、两种视角下的可见细节。先审查大轮廓，再制作细节，避免微缩好看而骑行看不清。
2. 简单物件继续用现有 Three.js 程序化建模：瓷器用旋转曲面，木作做真实连接和边缘，绳索/枝条用曲线。程序化不意味着拿方块、球和文字拼凑完成品。
3. 枣树、雪街、复杂屋檐等优先制作独立 GLB 模型；需要可编辑源文件及贴图。当前未在 PATH 中发现 Blender，正式制作前确认可用建模工具；不把建模软件已就绪当作事实。
4. 组件库只提供基础树木、椅子、木板等部件；记录许可证，统一尺寸、颜色、材质后组合。不用来替代整首歌的设计。
5. 一个模型资产同时供仓库预览、地图放置和骑行使用。预览由模型渲染，防止卡面插画精致而场景实物不一致。

### 资产字段与接入

设计表应按歌曲稳定 ID 登记 `kind / assetId / value / footprint / height / roadClearance / effect / source`。同名异人歌曲不能只靠歌名匹配。后续迁移只改变原装饰卡的外观，不自动转换其他类型。

首批建议占地从 2×2 到 6×4 米，最大高度约 5 米，正式尺寸随两种镜头预览调整。用占地包围盒或半径进行地形、物件冲突、道路净空判断；不能继续统一 4 米间距。骑行间隔由前后物件占地与留白决定，不沿用固定 9 米。

现有库存、放置坐标与歌曲 ID 保留。地图编辑器和骑行共用同一模型工厂；骑行允许调整展示朝向，以保证正面可见，但保留摆放顺序与左右关系。大海地图的观景台可适配岸边，森林/江南采用陆地观景台，绝不悬空或侵入车道。夜灯在白天依靠实体轮廓辨识，不要求用户换夜景才能看清。

### 性能制作目标（需实测，尚非保证）

- 小摆件约 1–3 千三角面，主景观约 5–12 千；远景去掉枣、裂纹等近景细节。
- 共享木材、金属、叶片材质，复用几何与贴图；重复花叶合批，避免每朵花单独申请材质和大量 draw call。
- 全场最多同时播放两组装饰粒子效果，屏外暂停，离开视野清理；烟火设置每局单次触发和范围上限。
- 放置幽灵、撤回物件、切地图时正确释放实例；共享资产使用引用管理，避免误释放其他物件的材质。
- 验收两个视角、三种地图及白天/夜间，比较最大 50 件摆放前后的帧时与资源增长，达不到预算就降细节。

## 道具精修

八种功能及现有等级数值不变。道具卡预览显示实体，局内释放显示简洁反馈：护盾以心形护符为核心；磁铁使用金属磁环并显示吸币弧线；守护信物展示双星吊坠；勇气展示羽翼徽章；茶盏补上釉面、盏托与蒸汽；冰晶沙漏应有框架、玻璃与流沙；计时器做真正可辨识的翻页数字；怀表补表冠、短链、刻度与倒转指针。不是把整个道具实体放大悬在骑手头上。

《朋友》现有加速可以保留，表现优先体现同行支援，避免与守护信物复用同一双星效果。新道具候选等剩余曲目核对后再评估，不能按新歌名自动塞进已有功能。
